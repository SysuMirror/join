# 2026-09-05 岗位区滚动渐显修复（reveal 误触发）

## 背景

用户反馈「往下滑后的岗位等文本组件也要有渐显效果」。排查发现渐显 `v-reveal` **机制本身存在，但未在滚动时触发**——岗位区在首屏加载时就已被标为已显示，滚动下去看不到渐显过程。

## 根因

`HomeView.vue` 的 `v-reveal` 用 `IntersectionObserver` 监听元素进入视口，配置为：

```ts
{ threshold: 0.08 }
```

当 Hero 占满 `100vh`、岗位区 `.band` 恰好贴着视口**底部边缘**时，`.band` 内元素（公告/板块头/职位行）在页面加载瞬间就被判定「已相交」，observer 回调立即给它们加了 `in` 类 → 渐显动画在首屏就播完，用户滚下去时早已显示完毕。

经 CDP 验证：滚动回顶部（scrollY=0）后，`.announce/.section-head/.job-row` 仍带 `reveal in`、opacity=1，确证误触发。

## 修复

调整 observer，让元素必须**真正滚入视口下方 8% 以上**才触发渐显：

```ts
{ threshold: 0.12, rootMargin: '0px 0px -8% 0px' }
```

- `rootMargin` 底部收缩 `-8%`：把「进入视口」的判定边界上移，元素必须滚过视口底部 8% 净空区才触发，避免贴边误判。
- `threshold` 提到 0.12，保证足够进入。

同时给岗位区内容加了**逐级错落延迟**（公告 80ms → 板块头 160ms → 职位行 `i*70ms` → 页脚 240ms），形成层次渐显。并微调 `.reveal` 位移（20px→28px）、时长（0.7s→0.85s）让效果更明显。

## 验证

CDP 检查：页面初始（scrollY=0）所有岗位区元素 `opacity=0`、class 仅 `reveal`（无 `in`）；滚动到岗位区后依次获得 `in`、opacity→1。`.foot` 在更下方不立即触发，随滚动再触发（正确）。

> ⚠️ 排查中另发现后端 dev server 未运行导致前端请求 `/api/jobs` 报 500、职位区显示 0 职位 —— 与渐显无关，属本地环境问题，启动 `server` 后恢复正常。
