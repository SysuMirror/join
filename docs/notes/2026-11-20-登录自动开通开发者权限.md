# 登录自动开通开发者权限（2026-11-20）

## 背景

此前用户要拿到 UniSSO 的 `is_developer=true`，必须走「加入软工集市团队」流程：
先有一份信息完整的简历，再点「加入软工集市团队」，由服务端调用
`POST /api/oauth/developer/update` 开通。用户反馈这一步应该免掉 ——
拿到集市身份登录，就应当自动成为开发者。

## 本次改动

### 后端

- `services/developer-sync.ts`
  - 新增 `autoGrantDeveloperOnLogin(user)`：登录成功后调用 UniSSO 开通开发者权限。
  - 跳过条件：已是开发者（`sso_developer=1`）、账号已退出（`status!=active`）、
    缺少邮箱、UniSSO 未配置。
  - 请求最多等 4 秒（`LOGIN_SYNC_TIMEOUT_MS`）；失败只打日志，**不阻断登录**，
    下次登录自动重试。成功后立即 `db.persist()` 写回 `sso_developer` / `sso_developer_at`。
- `unisso.ts`：`updateUnissoDeveloper(email, isDeveloper, timeoutMs = 12000)`
  增加超时参数，登录路径传 4 秒，后台/报名路径仍用 12 秒。
- `routes/auth.ts`
  - `persistUnissoLogin()`（邮箱密码无感登录、静默 SSO `sso/try` 共用）在
    `ensureDeveloperProfile()` 之后调用 `autoGrantDeveloperOnLogin()`。
  - OAuth 回调 `/api/auth/sso/callback` 同样在登录落地时自动开通。
  - 登录响应里的 `developer` claim 仍优先使用：若 SSO 已返回 `developer=true`，
    本地标记直接置位，不再多发一次 M2M 请求。
- `routes/me.ts`
  - `POST /api/me/join-team` 不再要求简历存在/完整，退化为「手动重试开通」。
  - `GET /api/me/join-team` 的 `ready` 改为表示「当前是否可重试」，`missing_fields` 恒为空。

### 前端

- `/join-team` 从「三步加入流程」改为「开发者身份」状态页：
  已开通时展示成功状态；未开通时提示登录时已自动开通、可点「重试开通」。
- 首页按钮「加入软工集市团队」→「成为开发者」；
  岗位页横幅改为「登录集市统一身份即自动成为开发者」；
  个人主页「去开通」→「重试开通」。

## 部署 / 验证

1. `cd server && npm run build`；`cd web && npm run build`。
2. `supervisorctl -c ~/deploy/supervisord.conf restart deploy-JyekPlhqwQ`。
3. 用一个未开通过开发者权限的账号登录，检查：
   - 登录响应 `user.sso_developer === true`；
   - UniSSO 侧该账号 `developer` 为 true；
   - `~/data/join-store.json` 中该用户 `sso_developer=1` 且 `sso_developer_at` 已写入；
   - UniSSO 不可用时登录仍成功，日志有 `[unisso] 开发者权限同步失败/异常`。

## 注意

- 自动开通不区分院内/院外（与原有「加入团队」入口一致）；只有 `status=exited`
  的账号会被跳过。
- 若管理员需要撤销某人的开发者权限，需要同时把本地 `sso_developer` 置 0 或调用
  `developer/update` 的 `is_developer=false`，否则下次登录会被自动重新开通。
