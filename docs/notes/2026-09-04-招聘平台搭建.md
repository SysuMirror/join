# 2026-09-04 招聘平台 join-platform 搭建

## 背景

新建**招聘投递站**（域名 `join.ssemarket.cn`），风格对齐 `developer-api`。核心诉求：
- 招聘从简、页面一两个即可；投递后初审通过**自动提交申请到开发者平台审核**。
- 上传 git、生成打包示例 `zip`；环境变量不落包，由部署平台注入，用 `.gitignore` 忽略。

## 结论

招聘平台（`基础服务/join-platform`）= Vue3 前端 + Express/TS(ESM strict) 后端 + 单 JSON 存储（本地 + MinIO 双写）。与开发者平台互联方式：**本站在开发者平台注册为「模块」**，用 **SM2 签名**调用其 **OA 审批接口**。

### 与开发者平台互联的具体格式

开发者平台 `developer.ssemarket.cn` 的 OA 开放接口（`docs/内部API调用指南.md` §3.5）：

| 接口 | scope | 说明 |
|------|-------|------|
| `POST /api/open/oa/submit` | `oa.submit` | 提交审批单，`oaid` 模块内唯一（重复提交 409 幂等） |
| `GET  /api/open/oa/query?oaid=` | `oa.query` | 查询审批状态与流转轨迹 |

- 鉴权头：`x-model-authorization = base64url(slug).base64url(ts).base64url(nonce).base64url(sign)` + `x-model-query-time`。
- 签名串：`{slug}\n{ts}\n{nonce}\n{queryTime}`，SM2withSM3（`hash:true, der:false`），sign 为 hex 文本按 UTF-8 再 base64url。
- **注意**：Go/工作台侧要求 sign 段解码后为 64 字节裸 r||s（binarySign），但开发者平台自身验签按 hex 文本解回，故我们发平台用 `base64url(hex文本)`，与官网 Node 示例一致。

### 数据流

```mermaid
flowchart LR
  C[候选人投递 /api/jobs/:slug/apply] --> P[库 applications status=pending]
  P --> A[管理员 /admin 初审通过]
```

## 关键路径 / 命令

- 本地开发：`server` 目录 `cp .env.example .env` → `npm run dev`(:8080)；`web` 目录 `npm run dev`(:5175)。
- 打包：`powershell -ExecutionPolicy Bypass -File .\deploy\pack-sseinfra.ps1` → `join-platform-sseinfra.zip`（预构建 dist，敏感值不落包）。
- 部署：SSE Deploy（sseinfra 组容器，无 Docker），模块名建议 `join-platform`，监听 `0.0.0.0:$PORT`。

## 登录 / 邮件能力（本次追加）

按需求新增「邮箱验证码登录 + 预留 SSE Market SSO」，并接入 SMTP 发信：

- **邮箱验证码登录**（默认开启 `JOIN_MAIL_LOGIN=true`）：
  - `POST /api/auth/code` 发送 6 位验证码到邮箱（nodemailer，5 分钟有效，同邮箱 60s 间隔防轰炸）。
  - `POST /api/auth/login` 校验验证码 → 建/取用户 → 签发 HMAC 会话 token（7 天）。
  - `/api/auth/me`、`/api/auth/logout`。
- **管理端鉴权**改造：`/api/admin/*` 从「口令」改为「登录会话 + 白名单」。登录用户需在 `JOIN_ADMIN_EMAILS`（逗号分隔）内才可进入 `/admin` 审核页。`x-admin-token` / `Bearer <JOIN_ADMIN_TOKEN>` 保留为兼容备选。
- **SSE Market SSO（预留）**：`JOIN_SSO_ENABLED=true` + `SSEAPI_OAUTH_*` 后可跳转集市账号登录；`/api/auth/sso/callback` 暂返 501，待接入 token 交换。
- 数据模型新增 `users` / `verify_codes` 两张表（单 JSON 存储，migrate 兼容旧库）。

### 邮件/SMTP 关键点

- 复用 `developer-api` 的 `services/mail.ts` 风格：兼容 `SMTP_HOST/PORT/USER/PASS/FROM` 与平台风格 `SMTP_ADDR=host:port`、`SMTP_EMAIL_USERNAME/PASSWORD`。
- 未配置 SMTP 时：验证码走降级（不发邮件）；本地联调设 `JOIN_MAIL_DEBUG=true` 会把验证码回显到服务端日志（生产关闭）。
- 邮箱/SSO 配置见 `server/.env.example`，均由部署平台注入。

## 环境变量（部署平台注入）

| 变量 | 必填 | 说明 |
|------|------|------|
| `JOIN_DEV_MODULE_SLUG` | ✅ | 本站在开发者平台注册的模块 slug |
| `JOIN_DEV_MODULE_PRIVATE_KEY` | ✅ | 注册模块时一次性下发的模块私钥（64 hex） |
| `JOIN_SESSION_SECRET` | ✅ | 登录会话签名密钥（随机长字符串） |
| `JOIN_ADMIN_EMAILS` | ✅ | 管理端白名单邮箱（逗号分隔） |
| `SMTP_HOST/PORT/USER/PASS/FROM` | ✅ | SMTP 发信配置（收验证码必需） |
| `JOIN_MAIL_LOGIN` | 可选 | 是否启用邮箱登录，默认 `true` |
| `JOIN_ADMIN_TOKEN` | 可选 | 兼容旧式管理口令（备选） |
| `DEVELOPER_API_URL` | 可选 | 开发者平台 Base（默认 `https://developer.ssemarket.cn`） |
| `PUBLIC_BASE` | 可选 | 站点公网根（默认 `https://join.ssemarket.cn`） |
| `JOIN_SSO_ENABLED` / `SSEAPI_OAUTH_*` | 可选 | SSE Market SSO（预留，未启用） |
| `MINIO_*` | 可选 | 四项全配启用对象存储 |

缺必填项时 `deploy.sh` 与服务启动双重 fail-fast。

## 验证

- `server npm run build` 与 `web npm run build` 全绿。
- 用临时 mock 开发者平台验证完整链路：投递 → 初审通过 → 自动推送 OA（`oaid=join-1`, `oa_status=pending`, timeline 1 条）→ 轮询回填（mock 批准后 `oa_status=approved`, timeline 2 条）。
- 指向真实开发者平台（占位私钥）验证 SM2 签名格式正确：返回 `[401] 模块不存在或已停用`（因占位 slug 未在平台注册，非签名错）。
- zip 打包校验：无 `.env`/`node_modules`/`data`/`.npm-cache`；关键文件齐全。
- 邮箱登录链路（`JOIN_MAIL_DEBUG=true` 无 SMTP 回显验证码）：`/auth/code` → 日志取码 → `/auth/login` 登录成功，`is_admin=true`（白名单生效）；`/auth/me` 返回用户，`/admin/jobs` 鉴权通过。

## 未决事项

- 部署前需在开发者平台真实注册模块、申请 `oa` 组权限，并把真实私钥/口令/SMTP 注入部署环境。
- SSE Market SSO 目前只预留入口，`/sso/callback` 待接入（需配置 `SSEAPI_OAUTH_APP_SECRET`）。
- 目前「初审通过 → 推送 OA」由人工点击触发；「OA 状态回填」靠管理页轮询，未做定时自动扫描。
- 验证码明文存于单 JSON 文件（本平台简化场景）；生产量大时建议换 Redis 存放验证码与会话。
