# 2026-11-20 接入新版开发者平台（项目广场）

## 背景

原来的「初审通过 → SM2 签名推 OA」链路只存在于代码里：`submitOa` 没有任何调用点，
`oa_oid` 在服务端从不赋值，只有管理页的「刷新审批状态」在查一个永远为空的字段。新版

开发者平台（`SysuMirror/developer`，`dev` 分支）改为由**它自己**开放两个接口给 join 调：

| 接口 | 说明 |
|------|------|
| `GET /api/join/projects` | 项目发现，只回 `id` / `title`，支持 `q`、`page`、`pageSize` |
| `POST /api/join/applies` | 代用户提交 participant 申请，字段 `ssoSub`、`projectId`、`resumeUrl`、`note` |

鉴权是共享密钥：`Authorization: Bearer <JOIN_API_KEY>`（也接受 `X-Api-Key`）。对方未配置
密钥时整组返回 503。

## join 侧实现

- `server/src/services/developer-platform.ts`：调用封装、8 秒超时、错误统一成
  `DeveloperPlatformError`。
- `server/src/routes/developer.ts`：挂在 `/api/developer`。
  - `GET /projects`：公开代理，未登录也能浏览。
  - `POST /applications`：登录后提交；把本地 `users.sso_sub` 作为 `ssoSub`。
  - `GET /applications`：返回本地留档（开发者平台没有状态查询接口，记录的是提交时状态）。
  - `GET /resumes/:token`：简历外链（见下）。
- `server/src/services/resume-link.ts`：简历外链签名与路径校验。
- 前端 `web/src/views/ProjectsView.vue` + 路由 `/projects` + 顶栏「项目广场」。

## 简历外链

开发者平台的 leader 是另一个站点上的用户，不能走 `/api/me/resumes/:id/file` 的登录态。
提交时生成 `…/api/developer/resumes/<id>.<exp>.<hmac>`，链接本身即凭证，默认 90 天有效。
签名密钥优先用 `JOIN_RESUME_LINK_SECRET`，留空时复用 `JOIN_SESSION_SECRET`。

## 配置

| 变量 | 说明 |
|------|------|
| `JOIN_API_KEY` | 与开发者平台侧完全一致；留空时只有项目广场 503，网站照常启动 |
| `JOIN_RESUME_LINK_SECRET` | 可选，简历外链签名密钥 |
| `JOIN_RESUME_LINK_DAYS` | 可选，默认 90 |
| `DEVELOPER_API_URL` | 开发者平台 Base |

旧的 `JOIN_DEV_MODULE_SLUG` / `JOIN_DEV_MODULE_PRIVATE_KEY`、`server/src/dev-platform.ts`、
`server/src/sm2-auth.ts`、`sm-crypto` 依赖与后台「刷新审批状态」已删除；历史 `oa_*` 字段保留
（只读展示，不再更新）。

## 验证

本地用 mock 开发者平台跑通：

- 未登录 `POST /api/developer/applications` → 401；
- 登录后提交 → 200，mock 收到 `ssoSub=sub-123`、`projectId=7`、`note`；
- mock 抓取 `resumeUrl` → 200（签名链接无需登录）；
- 篡改签名 / 过期链接 → 403；
- `JOIN_API_KEY` 未配置 → 503；与对方密钥不一致 → 502，提示检查密钥。

## 上线

1. 部署新版开发者平台（Node 22+、MySQL 8），注入 `JOIN_API_KEY`，并确认
   `/api/join/projects` 可访问；
2. 在部署平台给 join 注入同一个 `JOIN_API_KEY`，并把 `DEVELOPER_API_URL` 指向新平台
   （不要手改 supervisor 配置）；
3. 重新构建 `server/dist`、`web/dist` 并重启受管进程。

未注入密钥时项目广场会提示「开发者平台接入尚未配置」，其余功能不受影响。
